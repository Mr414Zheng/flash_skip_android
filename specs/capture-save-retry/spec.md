## 目标与已确认约束

用户保存采集结果时，成功、部分失败、重试和旧操作均有可验证的结果，且保存不会意外开启自动执行。

用户已确认：

1. 关闭目标开关成功、样本保存失败时，目标保持关闭，不回滚为开启。
2. 保存重试依赖原会话仍有效，不得借用后续新会话完成旧操作。

## 范围与术语

范围包括 `finish(sessionId)`、两份存储的提交顺序、规则目录就绪检查，以及保存失败后的界面重试入口。

- **本试点的可保存会话**：在协调器取得操作锁并检查状态时，当前会话 ID 与请求相同，且为带 `pendingSample` 的 `CAPTURED`，或带 `pendingObservedCandidate` 的 `AWAITING_CONFIRMATION`。这是状态上的保存资格，不额外保证检查时仍在时间期限内；已确认约束中的“原会话仍有效”在本试点按此判定。
- **失效操作**：会话已保存、取消、替换，或已因超时、服务断连等原因转为不可保存状态。返回 `Stale`，不得继续写入。
- **关闭提交**：`FlashSkipStore.setAppEnabled(target, false)` 已成功持久化。
- **保存提交**：一次 `RuleCaptureStore.update` 原子追加样本、清除会话及该目标的语义差分证据。
- **目录就绪**：目录的 `sourceSamples` 等于当前持久化样本，该目标分析为 `READY`，且最终目录包含其可执行规则。
- **相同保存操作**：同一会话 ID 的保存请求；不按目标包名或样本内容去重不同会话。

本试点要求存储读取正常，使用通过现有安全策略的合法样本。注入的写入 `IOException` 表示该次写入未提交；提交成功但返回未送达单列为 AC-08。

载荷缺失的会话不具备保存资格，返回 `Stale` 且不写入。取消或既有超时/断连失效转换与保存使用同一操作锁：失效转换先成功提交时，后续保存返回 `Stale`；保存先通过校验并成功提交时，后续针对原会话的操作不得撤销已保存样本。测试控制这两种顺序，不新增保存过程中的期限检查。

不涉及：节点识别算法、点击策略、规则生成门槛、跨进程自动重试、损坏数据恢复、存储格式迁移、跨库事务、新的超时或服务重连策略。到达期限但超时状态转换尚未执行的竞争，沿用现有调度，不在本试点新增严格截止保证。

## 用户流程与状态契约

1. 用户在已采集状态选择“保存”，或在候选状态明确选择“确认并保存”。
2. 协调器串行检查会话，先关闭目标开关，再提交采集状态。
3. 成功后展示已保存的实际状态；保存提交时目标关闭，后续只有合法的显式开启请求才能开启。
4. 写入失败时显示失败并提供原操作的重试入口。重试执行时再次校验原会话。
5. 目录异步就绪不自动打开开关，也不自动重放此前被拒绝的开启请求。

### 状态观察边界

下表及 AC 的状态断言描述本操作提交或失败后、其他独立操作生效前的快照。保存、重试及目录发布不得自行开启目标；后续合法开启、新建会话或删除数据产生的变化不违反保存契约。并发测试分别记录“保存提交快照”和“全部交错操作结束快照”，不得要求后者始终关闭或始终没有会话。

| 边界结果 | 目标开关 | 采集样本与会话 | 返回/界面语义 |
| --- | --- | --- | --- |
| 关闭提交失败 | 原值 | 原样 | `Failure(STORAGE)`，可请求重试 |
| 关闭成功、保存提交失败 | 关闭 | 原样 | `Failure(STORAGE)`，可请求重试 |
| 关闭已提交、保存未提交时协程取消 | 关闭 | 原样 | 传播取消异常；新调用重新校验原会话 |
| 两次提交成功 | 关闭 | 新增一份样本、会话清除 | `Success`，按目录状态展示结果 |
| 请求会话已失效 | 不变 | 不变 | `Stale`，不能当作本次新增成功 |

“原样”指该保存操作没有改变原样本和待保存证据；失败后其他合法操作、超时或断连仍可终结会话。关闭失败时原开关可能仍为开启，此时依靠现有采集阻塞状态阻止自动执行，不能声称开关已关闭。

## 验收条件

### AC-01 合法样本保存成功

给定可保存的 `CAPTURED` 会话、正常存储，以及目标和其他应用的已有数据：

- 保存必须在关闭提交完成后，才执行保存提交。
- 新增恰好一份本会话样本，保留既有样本；清除当前会话和本目标的语义差分证据。
- 保存提交快照中目标关闭，其他目标的开关、样本、语义差分证据及执行记录不变；后续变化按“状态观察边界”判定。
- 返回 `Success`；目录暂未就绪时不得展示为已启用或可立即开启。

### AC-02 关闭目标开关失败

给定可保存会话，在关闭提交前注入 `IOException`：

- 返回 `Failure(STORAGE)`；不得调用保存提交。
- 原开关、样本、会话及待保存证据保持不变；该会话的采集阻塞状态保持不变。
- 界面显示存储失败并提供原保存操作的重试入口，不展示保存成功。

### AC-03 关闭成功、保存样本失败

给定可保存会话，关闭已提交，在保存提交前注入 `IOException`：

- 返回 `Failure(STORAGE)`，目标保持关闭，不补偿恢复旧开关。
- 已有样本、会话、待保存证据和语义差分证据保持不变。
- 界面提供重试；在原会话仍可保存期间，采集阻塞仍存在，开启请求仍被拒绝。

同一中间状态若由协程取消结束，必须传播 `CancellationException`，不转换为 `Failure(STORAGE)`；目标保持关闭，样本、原会话和待保存证据保留，操作锁释放。该取消不要求 UI 新增重试入口；新调用协程可按 AC-04 重新校验并保存，不涉及跨进程恢复。

### AC-04 部分失败后重试成功

给定 AC-03 的存储失败或取消结果、恢复正常的写入，以及仍可保存的原会话：

- 重试仍使用原会话 ID；再次关闭目标属于允许的幂等操作。
- 重试的保存提交快照中，本会话样本恰好新增一份，既有样本保留，原会话及本目标差分证据清除，目标关闭。
- 由 UI 存储失败重试成功时，清除旧失败反馈和重试入口，按目录实际状态展示保存结果；取消后的直接调用不承诺已销毁 UI 的反馈。
- AC-02 后恢复写入的重试也应满足同样的保存提交快照。

### AC-05 重复、旧会话和失效操作

- 对同一可保存会话顺序或并发提交两次保存，最多一次追加样本；成功提交后的重复请求返回 `Stale`，且不写入任一存储。
- 会话已取消、替换或已转为 `FAILED` 后，旧 ID 的保存返回 `Stale`，不写任一存储。
- 阶段为 `CAPTURED` / `AWAITING_CONFIRMATION` 但对应载荷缺失时，返回 `Stale`，不写任一存储。
- 保存与取消/失效转换竞争时，按锁内串行提交顺序判定；保存先成功提交的样本不得被针对旧会话的后续操作撤销。
- UI 的“重试”保持原 ID，不读取新会话 ID 来替换旧操作；不损坏新会话或无关目标。
- 同一 UI 主动开始另一个操作时，旧重试可被替换或清除；不要求保留历史重试入口。
- 对同一目标的后续合法新会话仍可正常保存，不实施按包名的全局去重。

### AC-06 保存与开启请求交错

开启条件以请求取得同一操作锁后读取的状态为准：

- 会话仍阻塞时，返回 `CAPTURE_IN_PROGRESS`；目录样本未同步时，返回 `RULES_UPDATING`。
- 目录同步但分析未就绪或最终规则为空时，返回 `RULE_NOT_READY`；以上情况均不得写入开启值。
- 开启请求等待正在保存的锁时，保存完成后重新检查状态；只有条件满足且该次为明确的用户开启请求，才允许开启。
- 没有用户开启请求时，保存、重试及目录更新都不能自动开启；已拒绝的请求不自动重试。
- 合法开启请求在保存后成功时，全部操作结束的开关允许为开启；保存提交快照仍必须为关闭。

上述等待锁行为通过协调器入口验证。当前 UI 在操作进行中禁用或忽略新输入，不要求排队执行开启请求；UI 测试验证该限制及操作结束后的显式开启，不新增请求队列。

### AC-07 人工确认候选保存

给定可保存的 `AWAITING_CONFIRMATION` 会话：

- 候选出现或目录更新本身不保存样本，必须由用户明确确认并保存。
- 保存的证据类型为 `USER_CONFIRMED_UNREPORTED_CLICK`，不得标记为 `ACCESSIBILITY_CLICK`。
- AC-01～AC-06 的适用保存、失败、重试与隔离条件同样成立。
- 实际 `CAPTURED` 点击样本保留原真实点击证据类型。

### AC-08 已提交但调用方未收到成功结果

给定关闭和保存均已提交，分别考察结果到达调用方前取消等待，以及首次调用正常完成但调用方忽略成功返回：

- 保存提交快照中，本会话样本恰好新增一份、既有样本完整保留、原会话清除、目标关闭；不能因缺少返回值补偿回滚。后续合法开启或新建会话不要求回退到该快照。
- 对原 ID 再次调用保存返回 `Stale`，不写入任一存储，也不重复返回 `Success`。这与 AC-05 的重复请求契约相同。
- 在没有后续合法删除等变更的前提下，重新读取持久化状态，以本次样本 ID、目标及内容确认已提交结果；测试夹具保证本次样本 ID 原先不存在。`Stale` 本身不能证明曾经保存成功，也不能单凭该返回值推断保存失败。
- 协程取消继续传播，不伪装成普通存储失败；不要求保留跨进程 UI 重试入口。

取消等待与调用方忽略成功返回分别测试：前者断言取消传播，后者允许首次调用正常完成。均不增加保存回执或历史结果查询机制；UI 取消后是否存在重试入口不属于 AC-08 的承诺。
