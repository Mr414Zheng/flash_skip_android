## 任务清单

- [x] **T-01 修订稿审定**：核对 AC-01～AC-08、可保存会话、失效操作顺序、两类快照、UI/协调器边界及重复请求必须返回 `Stale` 的语义；保留两项已确认约束。产出：2026-10-13 用户明确同意修订规格并授权本阶段测试。
- [x] **T-02 测试支撑**（依赖 T-01）：建立合法 `CAPTURED` / `AWAITING_CONFIRMATION` 数据、其他目标数据、可控存储、目录、时钟与调度器；保证本次样本 ID 原先不存在。提供关闭提交前、关闭已提交但保存未提交、保存提交后返回前的屏障，并记录提交快照和全部操作结束快照。产出：可重复的测试支撑，无生产故障注入入口。
- [x] **T-03 保存成功与隔离**（依赖 T-02；AC-01、AC-07）：验证两次提交顺序、本会话样本恰好新增一份且既有样本保留、原会话/本目标差分证据清除，以及其他目标和记录不变。真实点击与确认候选分别保留正确证据类型；没有确认操作的候选不得被保存。
- [x] **T-04 关闭提交失败**（依赖 T-02；AC-02）：目标原开关为开启/关闭均覆盖；注入未提交的 `IOException`，验证没有采集提交、原状态保留、会话仍阻塞。
- [x] **T-05 部分失败与重试**（依赖 T-02；AC-03、AC-04、AC-07）：关闭成功后阻止样本提交，验证无补偿开启、证据不丢；解除故障后用原 ID 重试，只新增一次。两种采集输入分别覆盖，并补关闭提交失败后的重试。
- [x] **T-14 两次提交之间取消**（依赖 T-02；AC-03、AC-04、AC-07）：两种输入分别在关闭已提交、保存未提交的屏障取消调用；验证 `CancellationException` 传播、目标关闭、原会话/证据及既有样本保留。使用新协程和原 ID 重试，验证锁已释放、成功后只新增一份本次样本。不得要求取消产生 UI 存储失败提示或新重试入口。
- [x] **T-06 重复、失效与缺载荷请求**（依赖 T-02；AC-05）：正常存储下顺序/并发重复保存，首次有效请求成功，其余返回 `Stale` 且零写入。覆盖取消后重试、已转 FAILED 后重试、换新会话后旧请求、两种阶段缺载荷，均核对 `Stale` 与零写入。另以屏障分别控制取消/既有失效转换先提交、保存先成功提交，验证后者不被旧操作撤销；不新增超时机制。确认同一目标的新合法会话仍可保存。
- [x] **T-07 协调器保存与开启交错**（依赖 T-02；AC-06）：直接调用协调器，覆盖会话阻塞、保存中等待锁、保存后目录滞后、同步但无可用规则、同步且 READY 五种状态。分别控制目录在等待的开启请求校验前/后发布；对应断言拒绝或开启。记录保存提交时关闭、合法开启后允许开启的两份快照；被拒绝的请求不随目录更新重放，无请求也不得自启。
- [x] **T-08 提交成功但结果未送达**（依赖 T-02；AC-08）：在完成保存提交后、结果返回前取消等待；另覆盖首次成功调用正常完成但调用方忽略返回值后重试。前者断言取消传播，后者不要求异常；两者均断言旧 ID 重试返回 `Stale` 且零写入。按本次样本 ID、目标及内容重读确认恰好一份、既有样本保留，不能以 `Stale` 作为成功证据。分别增加保存后新建会话、保存后合法显式开启两个子用例，确认旧重试不清除新会话、不关闭已合法开启的目标。
- [x] **T-09 UI 反馈与重试绑定**（依赖 T-03～T-07；AC-01～AC-07）：验证存储失败反馈、原操作重试、成功后清除失败、目录反馈。操作中触发新输入，验证禁用或忽略且不排队；另测操作结束后的显式开启。保留旧 ViewModel 的失败重试状态，绕过该 ViewModel、直接调用同一协调器取消旧会话并建立新会话，再触发旧重试，确认 `Stale` 且新会话不变；同一 UI 主动执行新操作时，单独验证旧重试被替换或清除。订阅实际 `uiState`，不修改 UI 以制造测试入口。
- [x] **T-10 真实存储与目录集成**（依赖 T-03、T-05、T-08；AC-01、AC-04、AC-06～AC-08）：使用 Robolectric、真实 DataStore/Codec 和真实规则分析链。成功后关闭存储作用域，再创建新实例读取，检查证据类型、样本数、会话及开关。不得同时创建两个指向相同文件的活跃 DataStore。
- [x] **T-11 执行与分类**（依赖 T-03～T-10、T-14）：本轮完整 JVM 测试已执行，75 例通过、0 失败、0 错误、0 跳过，含 18 例 UI 和 5 例真实存储集成测试。运行测试，检查实际测试数与失败/跳过项；环境阻塞不计为通过。仅当出现产品偏差时提出最小修复，不为让测试通过改写已确认契约。
- [ ] **T-12 补充设备集成验证**（未完成，按用户要求不再推进）：已准备 Android 15 模拟器、安装京东并执行页面及采集入口探测，但未取得可重复开屏关闭页面，D-01～D-05 均未完成，D-05 暂停效果不可判定。2026-10-13 用户明确要求停止排查京东开屏广告无法复现的原因，并停止 T-12 剩余验证；保留证据和限制，不将停止视为验收通过。

## 执行命令与证据要求

本轮已在仓库根目录执行（本机使用 Android Studio JBR 提供 JDK）：

```sh
./gradlew :app:testDebugUnitTest
```

检查 `app/build/test-results/testDebugUnitTest/` 的 XML 和 `app/build/reports/tests/testDebugUnitTest/` 的报告；确认本试点测试类实际执行且没有关键跳过项。`NO-SOURCE` 不算通过。若结果来自缓存，记录对应代码版本；仅在需要新执行证据时使用 `--rerun-tasks`。

为设备验证构建/安装：

```sh
./gradlew :app:assembleDebug
./gradlew :app:installDebug
```

如后续修改生产代码，再执行与改动相关的构建和 `./gradlew :app:lintDebug`；不在仅写文档阶段运行这些命令。

每条结果记录：`证据层级（自动化/设备） / AC 编号 / 测试类与方法或设备步骤 / 实际结果 / 证据路径 / 提交版本 / 剩余限制`。并发及取消用例附提交点、取消点与各阶段快照。结果状态使用“通过、产品失败、环境阻塞、未执行”；无法完成 D-05 正向对照时，按实际原因记录失败或阻塞，暂停结论标为不可判定。修复后保留原失败原因和回归证明。
