## 架构和产品事实的使用边界

当前分层以领域模型与端口、应用协调、平台适配、存储和 UI 为边界。推广工作沿用现有依赖方向：Android 节点与系统调用位于平台层，业务状态转换由协调器负责，存储适配器负责编码与单次文件提交，UI 消费状态和结果。没有具体职责冲突或验证需要时，不为推进 SDD 新增抽象或拆模块。

以下只作为后续规格的事实基线：

- 两个 DataStore 各自提交，没有跨库原子事务；调用方的互斥锁不能当作跨进程恢复保证。
- CompositeRuleCatalog 异步派生规则，样本和目录可能短暂不同步；不同步时的消费行为应逐项规定。
- 自动执行已有歧义拒绝、期限与开关复核，以及动作后观察；目录失效与最近动作事件政策已按 SDD-003 修复，已列离线场景通过，不能扩大为设备结论。
- 采集已有窗口校验、安全过滤、预算和覆盖情况记录；扫描不完整不是节点不存在的证明。
- 当前 Codec 使用 v2 并有无效内容回退；P4 已确认兼容政策，SDD-006 和 SDD-007 已完成最小修复及本地验收，原空值回退偏差保留为修复前历史。诊断安装受 debug 条件控制，应用禁用备份；诊断边界已在 SDD-009 确认，首轮红例与 Release 运行证据阻塞保留。

上述事实的代码入口及待审定问题集中在 [能力清单](capabilities.md)。发现事实与需求冲突时，先记录偏差和影响，不把修改测试预期当作完成需求，也不因 P0 文档授权自动修复生产代码。

## 验收与证据约定

1. 每条 AC 描述输入、前提、操作和可观察结果，必要时说明禁止的副作用、并发顺序、失败与取消边界。
2. 用例通过公开业务入口或现有端口驱动；测试替身控制输入、故障和调度，不复制待测业务算法。并发用屏障和虚拟时钟，不靠真实休眠制造顺序。
3. 单次未提交写入失败、两次提交之间取消、提交后返回丢失分别记录，不混用故障语义。
4. 结果必须注明代码基线、测试类/方法或步骤、执行时间、实际数量、失败/错误/跳过项及限制。缓存结果注明来源；复用证据应确认代码与适用范围未改变。
5. `NO-SOURCE`、关键跳过项、没有设备和没有观察到点击都不是验收通过；没有独立用例也不等于已证实产品缺陷。
6. ViewModel 测试不代表 Compose 控件通过；Robolectric/存储重开不代表真实 Android 事件、断电或设备兼容通过。T-12 继续停止，不以新条目换名重做同一验证。
7. 测试报告、APK、截图、DataStore 导出和诊断日志不提交到源码仓库。文档可保留本机证据定位，但应声明全新检出不包含忽略的构建产物；P1 的 CI 报告策略见 [持续检查](ci.md)。
8. 项目结论分别报告规格覆盖、自动化验证、组件集成和设备限制，不用统一覆盖率或“全部完成”掩盖已停止项目。
