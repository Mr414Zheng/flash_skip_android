# SDD-006：持久化与兼容

状态：七项 P4 政策及默认行为已确认；用户续授权的最小生产修复与本地契约验收已完成。基线 main `40e6080`，日期 2026-10-14。实施见 [计划](plan.md)、[任务](tasks.md)，实际执行结果见 [验证](validation.md)。

## 目标与职责

两个 Preferences DataStore 分别持有开关／记录与采集状态；只承诺单库原子提交，不承诺跨库事务。Codec 负责格式兼容及条目隔离，Preferences stores 负责文件读写、初始化清理和安全过滤，协调器负责管理顺序。目录和执行消费方不能把不可用数据当成有效空库。

先交付规格与红例，后续已授权并完成最小生产修复。存储端口新增兼容默认实现的 reads 可用性观察，既有命令接口保持；持久化格式、依赖、构建与远端设置不变。SDD-001/T-12 未完成且停止，不进行设备验证或启动 P5。

## 验收条件

### AC-01 v2 往返与历史缺省

业务状态、待保存样本／待确认候选、语义证据及执行记录的已支持字段编码后读取保持等价。历史 v2 缺少 evidence 时默认 ACCESSIBILITY_CLICK；缺少候选监听字段时 false，缺少新增集合时空；记录缺少 actionAccepted 时沿用 method 非空的默认值，缺少 observation／timing 时为空。固定历史 wire 样本独立于当前编码器；忽略未知附加字段，不把兼容缺省推广为当前新事件可以缺少必要证据。

### AC-02 未知版本与不可解析整包

不存在或空白的既有存储值按正常空库处理。非空未知版本、缺失必需根结构或不可解析原文不得经初始化、普通更新、追加记录或管理删除被当前 v2 覆盖；相关操作必须明确失败。未知版本期间自动执行关闭，包括开关查询不能绕过未知记录版本。恢复仅在受支持数据有效重读或明确恢复后解除；本轮只模拟外部恢复写入，不新增恢复产品界面。

### AC-03 局部损坏与坏活动会话

已知 v2 中单个样本、语义证据或记录字段损坏，只丢弃该业务条目，其他合法条目及原顺序保留。可选诊断损坏不丢业务载荷。坏活动会话不能恢复采集；有效保存数据仍应可保留／展示，但不得因删除坏会话而解锁自动执行或普通写入。无法可靠解释的会话原文保留到明确恢复；合法但被既有安全政策拒绝的载荷属于 AC-05，不等同于格式损坏。

### AC-04 读取、失败与取消

读取 IOException 必须区别于健康空库，不得触发依赖这些读取结果的删除或覆盖。有效重新订阅／读取后能返回真实数据；本包不承诺后台无限自动重试。通过现有无健康状态字段的 Flow 接口测试读取显式失败；后续如采用健康状态接口，需另行审定接口方案并保持相同安全结果。动作开关读取失败返回 false。非 IO 异常和协程取消不能被当作成功或空数据吞掉。

### AC-05 安全过滤与初始化

继续使用既有 CaptureRuleSafetyPolicy，读、写、初始化使用同一策略。安全拒绝的数字节点样本及同目标／Activity 的语义证据移除，无关目标保留；不安全待保存载荷转换为既有失败阶段，清空载荷、监听和离开标记。清理写失败时读取仍过滤；清理与用户更新交错不能覆盖新数据。已落盘过滤结果在重开后保持。

### AC-06 v1 清理与共存

清除 `rule_capture_state_v1`、`action_records_v1`、`qq_music_enabled`、`taobao_enabled`、`jd_enabled`，不恢复旧开关、规则或记录。共存合法 v2 不变；清理 IO 失败不妨碍 v2 安全读取，不暗示清理已经完成。

### AC-07 单库提交、失败与重开

提交前失败或取消不改变该库原值；提交后取消／未取得返回不回滚已持久化内容。显式重试可完成尚未提交的写入。真实 PreferenceDataStoreFactory 文件与自有可取消 Job 必须在关闭后才重开；测试边界包装器只注入 IO 或调度，不替代编码与存储。跨库删除见 SDD-007/AC-03。

### AC-08 记录容量与管理隔离

每次追加前插并保留前 20 个合法记录，包含重复；不按时间戳重排。坏条目隔离之后取有效列表的前 20 条，超出容量的坏记录不得清空前面的合法记录。追加失败不破坏已有记录或目标开关；删除规则不清除记录。磁盘重开后保持顺序和内容。
