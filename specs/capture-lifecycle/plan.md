# 实施计划：SDD-004：采集生命周期

依据：[规格](spec.md)；实际执行见 [任务](tasks.md) 与 [验证记录](validation.md)。

## 初始规格测试阶段（已完成，修复授权见下文）

1. 先落盘已确认政策、基线参数与静态差异；用原生 JUnit／Robolectric 增加独立反例。
2. 复用提交屏障、窗口副本、节点故障 Shadow；双时钟和事件 uptime 独立控制。替身仅控制输入、故障与调度，不复制业务判断。
3. 先纯领域／协调器，再平台组件，最后检查真实服务和实际存储隔离可行性。无法可靠隔离时记录阻塞与最小接缝建议，不反射替换业务实现，不新增生产 API。
4. 覆盖正例、非法阶段、旧身份、精确期限及取消／存储失败；保留原 201 个完整测试身份。
5. 运行全量测试、debug 构建、Lint、28 个检查器测试、规格与产物门禁，按真实 XML 更新必需清单。失败分类并记录最小修复建议；本轮不实施生产修复。

窗口、节点与 Android 时钟仅在平台测试控制；会话提交由真实协调器处理。不存在真实设备证据，SDD-001/T-12 保持停止。

## 已授权修复的 ArchitecturePlan

用户后续授权五项政策的最小生产修复，以及完成真实服务集成所需的内部接缝；保留已有 453 个测试身份和预期，不提交／推送／PR，不改依赖／构建／远端设置，T-12 继续停止。

- 领域与状态归属：期限裁决及断连／恢复阶段分类仍在 RuleCaptureCoordinator 的操作锁内；新增内部可等待恢复入口供服务首次状态调用。通用 fail、finish 和存储格式保持原契约。
- 装配边界：AppContainer 保留生产默认构造，内部 runtime 接收应用 scope、实际 Preferences stores、双时钟与观察 dispatcher。服务使用每实例内部容器 factory，不引入全局测试 override；测试仍运行真实服务、协调器、目录、引擎与 DataStore。
- 生命周期：新引擎先同步暂停，再处理首次恢复状态；待确认监听关闭时仍暂停。interrupt／destroy 取消当前观察、窗口重试和到期任务；断连结算归应用 scope，避免服务 scope 已取消吞掉必要写入。旧 session 与旧生命周期任务不得影响新状态。
- 验证顺序：先原有期限／断连反例及证据政策组件，继而独立文件和可关闭 Job 的真实 DataStore 服务集成（连接、重连、配置、恢复、暂停、释放、失败），最后完整测试、构建、Lint 与证据门禁。测试端 clock/dispatcher 只控制输入和调度，不替代业务判断；真实系统和设备证据仍不在范围。
