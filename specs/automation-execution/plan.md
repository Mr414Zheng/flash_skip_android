# 实施计划：自动执行与动作确认

依据：[规格](spec.md)，基线 main `ad01dc7`。本轮先执行规格落盘与离线测试，再按用户明确授权完成三项跨包新增政策的最小生产修复；本包两项修复已通过本地离线验收。其余基线行为和参数保持既有范围。任务和结果分别见 [tasks.md](tasks.md)、[validation.md](validation.md)。

## 实现入口与职责

AutomationEngine、PostActionObserver、ActionRetryPolicy；PageGateway 平台实现以及 AccessibilityCandidateFinder、AccessibilityActionEvidence。

目录仅派生规则，引擎负责会话与动作决定，平台负责 Android 节点及动作证据。测试从现有公开入口或同模块内部策略入口驱动，不通过反射改写业务状态。沿用现有模块、端口和数据模型，不引入通用框架或存储迁移。

## 已复现差异与已实施修复

修复前，引擎保留启动规则而未复核最新目录，观察策略比较首次接受动作时间；离线测试保存了独立反例。已实施：当前目标/版本的有序可执行规则变化使活动会话失效，在动作和观察确认边界复核；支持事件严格晚于 lastActionAt，保留首次动作绝对观察期限。规则比较排除展示字段及其他目标；独立监听记住已观察到的失效，目录恢复不得复活旧查询。首次点击、手势和补点挂起返回接受结果时仍保留事实，随后结算 ABANDONED。

静态差异不是执行结果。先核对反例输入满足前置条件，再执行并保存断言失败；若失败出自测试环境或替身，修正测试后重跑。目标契约失败不能通过降低预期、忽略用例或标记预期异常变成通过。

## 实施顺序

1. 规格、政策和边界落盘，建立 AC → 任务 → 用例 → 结果追踪。
2. 按任务表先纯函数、后目录/策略、再引擎和平台/集成，复用既有测试支撑；三项政策各有独立反例。
3. 使用虚拟时间和明确屏障控制并发，阈值覆盖之前、相等及之后；替身只提供输入、故障和提交时刻，不复制业务判断。
4. 执行相关专项测试和既有 75 例，分别统计成功、失败、错误、跳过；检查器、构建、Lint 独立记录。先保存失败报告，再运行子集，避免覆盖证据。
5. 将确认的偏差和最小修复列入验证记录，按用户随后明确授权实施最小生产修复；补充挂起动作、观察与撤销后恢复的边界测试。完整离线套件、构建、Lint、规格及报告检查已通过；修复后证据已归档，结果在验证记录中单独登记。

## 测试与证据

现有 JUnit 4、coroutines-test 和 Robolectric 4.17 已足够；平台测试固定 SDK 36，必要的故障 Shadow 仅放测试源码。选择器查询、观察、记录和存储通过现有端口控制。长期收集作用域由测试清理，取消不能吞掉。

新增必需用例仅在已实现并核对真实方法标识后登记 `.ci/required-tests.json`，保留既有 75 例及失败/跳过/报告缺失阻断。若专项仍失败，CI 结论必须保持失败，不通过排除用例制造绿色结果。

## 完成条件与限制

每条 AC 有实际证据或明确缺口，必要回归通过，三项新增政策偏差闭环才可完成 P2。Robolectric 不证明真实设备、事件投递或点击效果。远端设置、依赖、构建配置、设备验证及已停止的 SDD-001/T-12 不在实施范围；不提交生成报告、APK 或诊断日志。
