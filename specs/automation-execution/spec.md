# SDD-003：自动执行与动作确认

状态：三项跨包新增政策已由用户审定，并已明确授权最小生产修复；本包目录变化使受影响会话失效、确认事件晚于最近接受动作两项政策已修复，本地离线验收通过。其余条款沿用基线行为与参数，本轮不扩大审定范围。基线为 main `ad01dc7`，依赖 [SDD-002](../rule-readiness/spec.md)。实施见 [计划](plan.md)、[任务](tasks.md)，证据见 [验证记录](validation.md)。

## 目标与边界

规定何时允许查询和动作、何时必须停止，以及何种证据能证明关闭。目录派生规则，引擎决定动作，平台生成证据；复用现有 `RuleCatalog`、`PageGateway`、存储和双时钟端口，不改公共 API、持久化模型或依赖。

验证限于确定性 JVM 和 Robolectric 离线适配器测试，不证明真实 Android 事件投递、设备点击或发布就绪。SDD-001/T-12 未完成并保持停止，不以平台测试之名恢复设备或京东复现任务。

## 当前实现事实

- [AutomationEngine](../../app/src/main/kotlin/com/zhenghuaizhi/flashskip/domain/automation/AutomationEngine.kt) 使用容量 64 的命令队列、前台会话和单调时钟；会话保存启动时的规则列表，并比较当前目标/版本的有序可执行规则；动作和观察确认边界复核最新目录。独立目录监听一旦观察到失效便保留失效标记，后续恢复不能复活旧会话。
- 点击/手势被接受后进入观察，接受和回调完成均不直接证明关闭。节点允许最多一次补点；仅确认关闭启动规则冷却。
- [PostActionObserver](../../app/src/main/kotlin/com/zhenghuaizhi/flashskip/domain/automation/PostActionObserver.kt) 以支持事件严格晚于最近接受动作 `lastActionAt` 判断关闭；首次动作 `acceptedAt` 确定的绝对观察期限不因补点延长。
- [AccessibilityPageGateway](../../app/src/main/kotlin/com/zhenghuaizhi/flashskip/platform/accessibility/AccessibilityPageGateway.kt) 负责提交前刷新和复核，候选查找和动作证据分别执行有预算的扫描。空索引、不可读和不完整不等于消失。

## 验收条件

### AC-01 会话资格与期限

目标开启且存在版本兼容规则时才建立会话；动作还须满足 Activity、启动延迟、该规则冷却和绝对期限。会话最多 10 秒，从原前台进入时间计算；同包 Activity/窗口变化不得延长期限，不得重新武装已终止会话。只有确认离开再进入可建立新会话；暂停恢复本身不触发动作。

### AC-02 查询与动作准入

仅唯一匹配可进入动作阶段；歧义和页面变化终止执行。不可读和遍历超限不能当作不存在，可继续检查其他选择器并在期限内重试。连续内容事件补充最新身份，不得持续推迟最早查询。过期查询、错误目标和迟到任务不能提交动作。

### AC-03 目录变化使受影响会话失效【已审定新增政策】

当前目标和版本适用规则的可执行内容或优先级顺序改变时，会话失效并停止新动作；其他目标、展示名称等元数据变化不影响它。比较规则 ID、目标/包、Activity 集合、选择器及其顺序、启动延迟、冷却、版本约束与规则顺序，排除展示名称、采集时间和分析展示字段。

首次点击、手势回退和补点前均复核最新目录；查询挂起期间撤销规则也不得提交动作。已经接受动作的会话保留 ABANDONED 未确认记录，不继续观察成成功，不自动重新武装；无动作时不捏造接受记录。挂起动作返回接受结果时，先保留已发生的接受事实再结算失效。监听已观察到的撤销具有持续效力，即使旧查询尚未返回而目录恢复，也不能复活旧会话；不声称捕获所有未向 StateFlow 订阅者投递的瞬态变化。

### AC-04 点击与手势边界

不可点击节点不得触发坐标手势；仅节点点击不支持时允许手势回退。平台提交前须复核页面、窗口、目标、取消状态和绝对期限。手势提交接受及完成回调都不是关闭证明；拒绝、取消、超时和迟到回调不得产生后续点击或恢复旧会话。

### AC-05 关闭确认

关闭需要相同消失证据稳定至少 200ms，并有严格晚于最近一次接受动作的支持事件。原窗口移除必须有后续窗口事件，内容事件不够。证据变化重新计时；到达观察/会话期限即不确认，即使稳定时间已满足。

隐藏、改文案、空索引、不完整扫描和页面切换本身均不足以确认；局部或完整扫描必须提供可信消失及上下文证据。原窗口消失还须有效的新窗口/页面上下文，不以窗口 ID 改变直接推断关闭。

### AC-06 补点及事件规则收紧

仅节点点击可补点一次：原目标仍唯一存在、页面身份一致、有动作证据、稳定至少 200ms、距上次接受至少 750ms、事件版本未改变，且未到观察期限。失败补点也消耗次数。补点接受后旧事件不能支持关闭确认，观察总期限仍从首次接受开始且不得延长。

### AC-07 失效、取消和迟到结果

离开目标、禁用、采集暂停生效、版本变化、目录失效、队列溢出或关闭引擎后不得继续新动作。暂停 API 返回表示命令已生效；恢复本身无动作。已接受动作保留未确认记录，不冒充成功；旧定时任务、查询返回或迟到回调不得重新武装会话。

### AC-08 记录与冷却

只有确认关闭写 CLOSED 并启动该规则冷却；动作接受但未确认写 ABANDONED，保留 `actionAccepted`、动作方式及观察结果。拒绝或未提交不得假装接受。终态先于记录写入生效；记录异常不能重复点击，协程取消继续传播。未确认/失败不启动成功冷却，其他规则冷却互相独立。

## 时间与扫描默认策略

以下沿用基线实现参数，本轮未重新审定或调整这些默认值，所有期限使用单调时钟，到达即停止；墙钟仅记录展示时间。

| 项目 | 默认值 |
| --- | --- |
| 查询去抖 / 不可读或超限重试 | 120ms / 250ms |
| 观察窗口 | 最多 2400ms，且不越过会话期限 |
| 首次观察 / 事件去抖 / 定时观察 | 250ms / 120ms / 400ms |
| 稳定证据 / 补点响应等待 | 200ms / 750ms |
| 页面回退 | 首次接受 1200ms 后，最多两次 |
| 手势等待 | 最多 1000ms，且不越过会话期限 |
| 引擎关闭清理 | 最多 500ms |
| 候选完整扫描 | 500 节点、深度 40、100ms |
| 动作证据局部扫描 / 完整页面扫描 | 64 节点、深度 8、60ms / 500 节点、深度 40、100ms |

阈值验证覆盖前一时刻、恰好到达和超过，使用虚拟调度/可注入时钟，不靠真实休眠。
