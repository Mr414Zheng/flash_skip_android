## 验证命令与适用范围

行为变化先执行相关专项测试，再执行完整 Debug 回归、构建、Lint 和原有门禁。使用仓库 wrapper、JDK 21 与已配置 SDK；不要通过改依赖、配置或远端设置绕过环境问题。

```sh
./gradlew :app:testDebugUnitTest --rerun-tasks
./gradlew :app:assembleDebug :app:lintDebug
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/ci/tests -v
PYTHONDONTWRITEBYTECODE=1 python3 scripts/ci/check_specs.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/ci/check_test_results.py --require-artifacts
git diff --check
```

专项测试可用 `:app:testDebugUnitTest --tests '完整测试类名'`。专项运行可能覆盖同目录 JUnit 报告，故完整测试必须位于专项之后；先归档失败证据，再生成本次完整报告，禁止把上次构建产物混入本次结论。产物检查要求 JUnit、HTML、Lint 与非空 APK，但不会自行证明报告属于本次提交，作者须核对运行和源状态。命令通过后不为追求更多日志重复完整测试。

新增测试按真实 `class + method + 参数后缀` 更新 [.ci/required-tests.json](../.ci/required-tests.json)。删改身份、参数化或断言必须说明需求依据并接受评审；同数量替换不等于保留回归。清单的 `baseline` 是生成时基线，不能拿它替代本次被测 head。修复前被后续失败截断的矩阵不能声称所有子项已执行。

纯文档本地只执行以下检查，不将历史 Android 结果标为本轮执行。远端 CI 的完整执行策略保持不变，只有获得交付授权后才推送触发。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/ci/check_specs.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/ci/tests -v
git diff --check
git diff --name-only
git ls-files --others --exclude-standard
```

核对已跟踪和未跟踪差异都只有预期文档；复用证据还须比较相关生产／测试／配置／清单与被测提交。文件未变仅允许复用相同范围的历史结果，不能声称当前工作树已有新 CI。

## 评审清单

- [ ] 作者给出“行为差异 → 完整 AC → 实现／调用方 → 测试类、方法或步骤 → 结果／限制”，多子条款分别有证据或缺口。
- [ ] 契约、实现事实、验证状态和执行决定分开；历史红例与停止决定保留。
- [ ] 评审者阅读测试断言及对应实现，确认 AC 引用在语义上相关；不能仅凭存在链接或总数判断覆盖。
- [ ] 核对测试身份、参数、预期与旧基线；按层级区分 JVM、ViewModel、Robolectric 组件、实际存储、真实服务类、Compose 和设备。
- [ ] 核对提交／运行／变体／报告来源；Debug≠Release，文件重开≠杀进程，STARTED≠页面到达，静态 Manifest≠OEM 备份实测。
- [ ] Release 阻塞、P5 两项 T-05、SDD-001/T-12 的未完成及停止状态没有被吞掉；独立评审和 QA 只在实际发生时归属。
- [ ] 当前授权和最终差异一致；提交、推送、PR、合并及远端设置按实际授权处理。

现有 [check_specs.py](../scripts/ci/check_specs.py) 检查编号、任务、仓库链接／标题锚点和 PR 字段；不访问外部链接验证实时可用性，不检查源码方法是否对应 AC，不判断产品声明真假。[check_test_results.py](../scripts/ci/check_test_results.py) 检查必需身份、失败／跳过和产物；不证明需求完整、报告新鲜度或真实设备行为。语义充分性由作者和评审者负责，脚本绿色不能覆盖人工发现的错误。

## PR 正文填写示例

保留现有三个字段，内容与字段名在**同一行**；规格引用写完整 AC，或提供至少 8 字的无契约变化原因；验证结果至少 8 字且包含真实结果和限制。以下两个是格式演练，产品修复示例不代表本轮发生了修复或执行 Android 测试。正式交付须用实际提交／命令／报告替换示例内容。

```text
规格引用：SDD-008/AC-02
无契约变化原因：保持已批准的固定确认期限契约，修正实现偏差。
验证结果：示例：补固定期限反例并执行专项及完整 Debug 验证；实际结果、提交和报告待实施后填写，不宣称设备通过。
```

```text
规格引用：
无契约变化原因：本次仅建立 P6 流程和追踪文档，不改变应用行为与产品契约。
验证结果：规格及链接检查、28 个检查器测试和差异检查通过；Android 复用 main 625091d 的 CI 38531810742，本轮未重跑。
```

格式通过仅表示字段完整。含“示例／待实施”的第一份正文不可作为真实交付验收报告；人工评审必须拒绝将其用于已完成声明。

## 交付与证据保存

默认在变更 PR 中更新适用验证记录，合并后结果直接交接；只有用户明确要求时才创建独立证据文档 PR，避免每次 CI 都再造一个需要新 CI 的文档提交。P6 最初授权止于本地文档；后续 PR 交付续授权见文末。以下交付流程只在已获相应授权时执行，合并仍需实际授权。

1. 记录工作树／提交、变更范围、专项与完整执行命令、时间、环境、测试身份、失败／错误／跳过、构建和 Lint 结果。失败、环境阻塞及未执行分别保留。
2. 推送后核对最新 PR head；记录 run ID、attempt、event、head 和实际 checkout SHA。PR merge ref 须核对父提交包含目标 head，不能将旧 head 绿灯移用到新提交。报告文档后续提交也须通过其自身最新检查。
3. 若已获合并授权，复核最新检查再合并；合并后的 main 是单独证据，不能用 PR 成功替代。记录 merge SHA 和 main push run。
4. 下载报告后核对 ZIP 名称、大小、digest、解包内容、完整测试身份及 checkout 来源；记录报告可访问性核验时间。工作流在 runner 验证 APK 非空但未上传 APK 二进制，不能宣称下载了 APK。
5. 原始报告留在忽略目录，提交摘要和可追踪运行链接。报告保留期为 14 天；过期不抹除历史成功，但不得继续声称仍可下载。错提交／来源不明报告不能支持当前结论；过期报告有已验证本地归档时可作历史证据并注明边界，不能伪装新运行。

交接最少包含：能力／AC、变更和契约、适用提交、run/attempt、环境与证据层级、测试身份差异、报告摘要和核验结果、未完成及停止项、下一步执行授权。诊断日志仍需按既有敏感内容要求检查，不提交 local.properties、密钥、构建物或原始日志。

## P6 拒绝错误结论演练

| 输入错误 | 现有脚本责任 | 人工裁决及记录位置 |
| --- | --- | --- |
| 引用不存在的 AC-99 | `check_pr`／仓库引用检查拒绝 | 不创建虚假编号规避；回到所属 spec |
| 使用旧／错提交报告或把过期报告写成仍可下载 | 结构检查可能通过；产物检查不验证 Git 对应关系或下载有效期 | 对照 checkout/head/attempt、源码差异和归档证明；拒绝用于当前结果，注明历史范围 |
| 保持总数却替换一个必需测试身份 | 原检查器负例 `test_renamed_case_with_same_total_cannot_hide_removal` 拒绝 | 核对删除／改名理由和断言，不通过改清单掩盖丢失回归 |
| Debug 关闭模式写为实际 Release 通过 | 字段可合法，脚本不识别该语义错误 | G-RELEASE 拒绝，要求实际 Release 执行 |
| ViewModel 通过写为 Compose 控件通过 | 字段可合法，脚本不识别该语义错误 | G-UI 拒绝，要求真实控件操作／语义证据 |
| T-12 停止写为通过 | 编号存在，脚本不读懂执行决定 | G-STOP 与原 tasks 拒绝；保持未完成且停止 |

这些是本次人工演练的拒绝裁决；不是新增 CI 能力。有效格式样例通过和无效 AC 拒绝用现有函数实际验证，同数量替换由现有测试实际执行；其余语义误报使用结构合法的正文演示脚本盲点后人工拒绝。
