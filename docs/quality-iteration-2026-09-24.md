## 流程与架构

主流程为：服务就绪 → 开始采集并暂停自动执行 → 锁定目标 → 捕获点击或确认候选 → 先关闭目标开关再保存规则 → 用户明确启用 → 唯一匹配并执行 → 查看记录或清除规则。

依赖方向保持 `ui → application/domain`、`application → domain`、`data → domain`、`platform → application/domain`，由 `AppContainer` 组装。领域和应用层未导入 Android/AndroidX；Android 节点访问及释放仍位于平台层。采集会话与规则来自 DataStore，界面和目录是派生状态。

## 本轮修复

| 编号 | 问题 | 修复与验证重点 |
| --- | --- | --- |
| Q-01 | 完成采集先清会话、后关闭开关，存在提前恢复执行的窗口 | 协调器串行化写操作，先持久化禁用，再提交样本；失败保持安全状态，重复和过期操作无副作用 |
| Q-02 | 手势回调丢失可使引擎及暂停命令永久等待 | 等待不超过 1 秒及剩余会话预算；引擎关闭/失败取消等待者，迟到回调不改变终态 |
| Q-03 | 诊断日志包含页面语义，采集订阅全部事件 | Release 关闭调试日志，Debug 仅记录状态、计数和耗时；日志不读取事件源；仅订阅实际处理的三类事件 |
| REV-001 | 旧服务断连任务可能读取并终止新会话 | 断连时绑定会话 ID；覆盖延迟断连、已完成会话和既有失败终态 |
| REV-002 | 同步扫描期间超时任务不能调度，可能越过期限提交手势 | 网关接收绝对截止时间，在系统派发前检查单调时钟及取消状态；扫描跨界时必须零派发 |
| REV-003 | 启用入口逐条校验通过，但规则 ID 碰撞使目录整组回退为空 | 通过领域目录校验当前样本及最终规则；拒绝过期目录和不可用规则，关闭始终允许 |

界面增加保存中的禁用状态及可重试错误提示；配置等待识别已经推进的会话，并保留原有服务失败原因。
